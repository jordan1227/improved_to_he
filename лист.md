One last loose end worth a quick check, since we're closing this out: is there a repair-kit or armor-degradation system elsewhere (outside these two scripts) that calls set_mask_condition(id, cond, ...) directly — e.g. triggered by anomaly damage, bullet hits, or a repair kit UI action? If such a system exists and doesn't check is_respirator_outfit first, it would happily create that "mask"/"t4" ini section on a respirator (since set_mask_condition doesn't care whether the mask cache was ever initialized), and once it exists, get_mask_condition would stop returning the harmless 100 default and start reflecting real degradation — bringing back a condition value even though the tooltip now hides it, and potentially feeding wrong severity/dirt numbers if anything else reads it later. Worth a search for other set_mask_condition( call sites just to be sure nothing writes to that ini section behind the respirator's back.
